# Market-GAN in TradeMaster

**Paper:** *Market-GAN: Adding Control to Financial Market Data Generation with Semantic Context* (AAAI 2024), [PDF](https://personal.ntu.edu.sg/boan/papers/AAAI24_MarketGAN.pdf) · [arXiv 2309.07708](https://arxiv.org/abs/2309.07708) (local copy: `articles/Market-GAN.pdf`)
**Upstream:** https://github.com/TradeMaster-NTU/Market-GAN @ `f0f201829e5d2b5c5df51658fe994ce0d41bcfd1` (2024-02-16), vendored without history.
The upstream `README.md` is kept. This file explains how the project is wired into TradeMaster.

## What it does

Market-GAN generates realistic daily market data (DJI constituents, 2000–2023) **controlled by semantic context**: market dynamics (bear, flat or bull), stock ticker, and recent price history. It is used for scenario simulation and training-data augmentation.

| Component (paper) | Idea | Code |
| --- | --- | --- |
| Market Dynamics Modeling (MDM) | Low-pass filter, slice at extrema, merge short segments to a minimum length, then cluster adjacent segments by DTW distance with linear-regression slope labels. The result is a dynamics label `d` for each window. | `MarketDynamicsModeling/` (a fork of TradeMaster's `tools/market_dynamics_labeling`), config `configs/market_dynamics_modeling/djia.py` |
| Contextual dataset | Pairs each window `X` with its context (history `H`, dynamics `d`, ticker `l`) | `data/conditional_data_preprocess.py`, `dataset/dataset.py` |
| Autoencoder | Embedding and recovery networks give a low-dimensional latent space (TimeGAN-style) | `models/EmbeddingNetwork.py`, `models/RecoveryNetwork.py` |
| Conditional GAN | Generator and discriminator conditioned on `(H, d, l)`. History is encoded separately. | `models/GeneratorNetwork.py`, `models/DiscriminatorNetwork.py`, `models/HistoryEmbedding.py`, `models/conditional_timegan.py` |
| Supervisors | A next-step supervisor plus context classifiers (TimesNet) that push generated data to match its context | `models/SupervisorNetwork.py`, `models/ConditionalSupervisor.py`, `models/TimesNet.py` |
| Two-stage training | (1) Pre-train the AE and supervisors to initialise the generator. (2) Adversarial training with the combined objectives. | `MarketGAN.py`, `main.py` |
| Evaluation / downstream | Alignment, fidelity and market-facts metrics, plus forecasting models (GRU, LSTM, RNN, TCN) trained on real data vs real + generated data | `metrics/`, `downstream_tasks/`, `service/` |

## Running it

Environment: the shared `../.venv-hft` (Python 3.10, torch 2.0.1+cu118). See the root README.

```bash
./run.sh help
./run.sh mdm            # I.  label DJI dynamics (required before any training)
./run.sh pretrain       # II. pre-train condition supervisors  -> output/DJI_pretrain_50
./run.sh train          #     train Market-GAN                  -> output/DJ30_V2_RT
./run.sh evaluate
./run.sh plot
./run.sh export         # III. export model for inference
./run.sh generate       #      generate augmented data
./run.sh prep-real && ./run.sh forecast-real && ./run.sh forecast-gan
```

To skip training, download the authors' checkpoint (SharePoint link in `README.md`) into `output/`. You still need `mdm` first, because the scripts read the labelled CSV.

## Adaptations vs upstream

- `run.sh` runs the upstream `.sh` files unchanged except for one on-the-fly rewrite: every hard-coded `cuda:1`/`cuda:2`/`cuda:3` becomes `$DEVICE` (default `cuda:0`). It also puts `.venv-hft/bin` first on `PATH` so their `python` calls use the shared environment.
- `MarketDynamicsModeling/configs/market_dynamics_modeling/djia.py`: `data_path` changed from `../Market_GAN_AAAI/data/DJI/DJI_data.csv` (the authors' local folder name) to `../data/DJI/DJI_data.csv`. The upstream README asks you to make this edit. Note that `mdm` **rewrites this config** after each run, adding result paths.
- `mmcv==1.7.1` needs `yapf<=0.40.1`, which is pinned in `requirements-hft.txt`. Otherwise config dumping crashes with `FormatCode() got an unexpected keyword argument 'verify'`.
- `cupy-cuda12x` from `AAAI_MarketGAN.yml` is left out because nothing imports it.
